<a id="quick-start"></a>

## 🚀 快速开始

1. **📦 安装并启用**
   - 在插件市场安装 <code>astrbot_plugin_daily_share</code>。

2. **🎯 添加接收目标**
   - 在要接收分享的当前会话发送 <code>/分享 添加当前</code>。
   - 或进入仪表盘，填写 QQ 号、群号或其他平台的会话 ID。
   - 多机器人实例时，在目标卡片中选择负责发送的机器人；单实例会自动绑定。

3. **📝 选择分享方式**
   - 只想发送文字：保持媒体能力关闭即可。
   - 需要自动分享：开启 <code>enable_auto_share</code>，设置全局时间和类型序列。
   - 需要指定内容：使用 <code>/分享 心情</code>、<code>/分享 新闻</code> 或自然语言触发。

4. **🧩 按需安装生活插件**
   - 需要生活状态、聊天上下文、联网证据、配图、视频、语音或 MemOS 时，安装
     [astrbot_plugin_daily_life](https://github.com/siciyuanweilai/astrbot_plugin_daily_life)。
   - 生活插件未安装时，纯文字分享、新闻接口、新闻长图、定时任务和普通平台发送仍可独立使用。

5. **🧪 完成首次验证**
   - 发送 <code>/分享 心情</code>，确认当前会话能收到文字分享。
   - 发送“看看微博热搜图片版”，确认新闻接口和长图发送链路。
   - 发送“分享一下今天的心情”，确认自然语言工具调用。

6. **🖥️ 打开仪表盘**
   - 在网页管理后台的插件详情页进入日常分享仪表盘。
   - 可继续调整目标、定时、类型序列、新闻源、媒体、QQ 空间和失败重试配置。

### 🧺 按场景补充

| 目标 | 需要开启或确认 |
| :--- | :--- |
| 新闻长图 | 新闻接口、新闻源和热搜长图配置；链接追问只读取成功发送的快照 |
| 图文、视频、语音 | 安装并配置 <code>astrbot_plugin_daily_life</code>，再打开对应媒体能力 |
| 个人微信 | 使用 <code>/sid</code> 输出的完整会话 ID，并确认框架已保存 <code>context_token</code> |
| QQ 空间 | 使用 OneBot，并确认适配器支持 <code>get_cookies</code> |
| 多个机器人 | 在目标卡片和 QQ 空间设置中分别选择负责发送的机器人实例 |

---

插件负责决定“何时分享、分享什么、发到哪里”；生活插件按需提供生活状态、联网证据和媒体生成能力。

## 📝 分享内容

| 类型 | 内容来源 | 适合场景 |
| :--- | :--- | :--- |
| <code>问候</code> | 当前时段、生活状态、聊天上下文 | 早安、晚安、日常招呼 |
| <code>新闻</code> | 热搜接口、新闻摘要、新闻长图 | 热点速览与原文追问 |
| <code>心情</code> | 当前状态、人设与上下文 | 文字、语音、配图或视频 |
| <code>知识</code> | 自定义知识库与联网证据 | 科普、技巧与趣味知识 |
| <code>推荐</code> | 自定义推荐库与联网证据 | 书影音、应用与生活推荐 |
| <code>自动</code> | 当前时段与类型序列 | 无需手动指定类型 |

知识库和推荐库支持自定义分类、子话题与类型前缀。成功分享会写入历史，用于去重、仪表盘展示和后续上下文参考。

<a id="news"></a>

## 📰 新闻与快照

支持微博、知乎、B站、抖音、快手、头条、百度、腾讯、夸克、36氪、51CTO、A站、爱范儿、网易、新浪、澎湃、第一财经、财联社等新闻源。

- 新闻优先使用接口提供的摘要、正文与原文链接。
- 背景资料不足时，可通过生活插件的公开检索入口补充证据。
- 新闻源可固定选择，也可从配置列表中随机选择。
- QQ 群聊和私聊会优先下载远程长图后发送，提高富媒体稳定性。
- 查询链接时不会重新抓取远程新闻，只读取成功发送时保存的 JSON 快照。
- 新闻序号参数支持阿拉伯数字、全角数字和中文数字，并拒绝年份、多序号等有歧义的输入；普通查询文本仍按新闻标题和摘要检索。

快照查询规则：

| 查询方式 | 读取内容 |
| :--- | :--- |
| 未指定新闻源 | 当前目标最后一次成功发送的新闻快照 |
| 指定新闻源 | 当前目标中该新闻源最后一次成功发送的新闻快照 |

例如依次发送：

~~~text
09:09  微博热搜
10:00  抖音热搜
11:00  微博热搜
~~~

此时默认查询读取“11:00 微博”，指定抖音读取“10:00 抖音”，指定微博读取“11:00 微博”。后台抓取和发送失败不会覆盖已有快照。

## ⏰ 定时与序列

| 调度方式 | 说明 |
| :--- | :--- |
| 固定时间 | 按每日指定时间执行 |
| 随机时段 | 在配置时段内生成随机执行时间 |
| 智能定时 | 结合配置策略生成执行任务 |
| 高级 Cron | 支持标准 5 位表达式（星期字段按 crontab 约定：0/7 为周日） |
| 独立目标定时 | 每个群聊或私聊可设置自己的时间和类型序列 |
| QQ 空间定时 | 使用独立时间、类型序列和随机延迟 |

普通分享、早报和 QQ 空间分别使用独立的随机延迟。随机时段的结束时间必须晚于开始时间，不支持跨天；智能定时的勿扰时段支持跨天。随机时段与智能定时任务会写入数据库，插件重启后可恢复尚未完成的任务。

目标卡片规则：

- 独立时间留空时跟随全局定时。
- 独立序列留空时跟随全局类型序列。
- 同时设置独立时间和独立序列时，该目标完全独立运行。

## 🧠 上下文与媒体

分享前可按目标读取平台聊天历史，并结合：

- 当前时段、生活状态与角色人设；
- 当天穿搭、发型、妆容与美甲；
- 私聊或群聊近期上下文；
- 当前生理节律、七日节律趋势与近期生活片段；
- 当前目标的关注事项、表达偏好、互动方式和熟悉用语；
- 群聊活跃程度与主动分享策略；
- 已发送主题与内容去重记录；
- 生活插件提供的 MemOS 长期记忆。

媒体能力默认由生活插件提供：

- 配图：依据分享文案生成图片；角色本人入镜时，当天穿搭与动态外观优先于人设和参考图中的旧造型。
- 视频：使用生成配图制作，图片与视频不会重复混发。
- 语音：适合问候和心情类型，失败时继续发送其他内容。
- 个人微信：图片生成独立发送副本，并自动清理临时文件。
- QQ 空间：当前仅发布文字与图片，不发布视频。

成功发送后才会回传活动与记忆；发送失败不会写入成功历史。

普通聊天的工具上下文只读取最近查询状态，新闻与 QQ 空间共用 150 毫秒等待预算；数据库繁忙时跳过注入，不在聊天钩子中联网查询。动态状态追加到当前请求，保留原有人设系统提示词。分享模型调用默认采用 `llm_timeout` 配置，显式较短时限仍会生效。

## 🧭 平台与目标

| 平台 | 支持场景 | 目标填写 | 注意事项 |
| :--- | :--- | :--- | :--- |
| QQ / OneBot (<code>aiocqhttp</code>) | 私聊、群聊、QQ 空间 | QQ 号或群号 | 多实例时选择负责发送的机器人 |
| 个人微信 (<code>weixin_oc</code>) | 个人私聊 | 会话 ID 或 <code>/分享 添加当前</code> | 需要框架已保存对应 <code>context_token</code> |
| WebChat / 其他平台 | 取决于适配器能力 | 优先使用 <code>/sid</code> 输出 | 主动发送能力由适配器决定 |

只有一个可用机器人实例时，仪表盘会自动绑定；存在多个实例时必须明确选择。插件内部保存完整会话标识，避免多机器人实例串线。

示例：

~~~text
群号：group-test-001
QQ 号 / 会话 ID：user-test-001
机器人实例：bot-main
~~~

内部保存为：

~~~text
bot-main:GroupMessage:group-test-001
bot-main:FriendMessage:user-test-001
~~~

个人微信专属处理只会对平台名或适配器元信息精确为 <code>weixin_oc</code> 的实例启用。

## 🌐 QQ 空间

### ✨ 发布与操作

- 发布文字或图片说说；
- 查看自己的说说、指定用户动态和说说详情；
- 点赞、评论与删除自己的说说；
- 按相册 ID 和照片 `picKey` 查看相册照片及评论，并发表评论到指定照片；
- 返回发布时间、说说 ID 和媒体数量，便于继续操作；
- 在多机器人环境中单独选择 QQ 空间实例。

QQ 空间登录态与查询缓存按实际机器人实例隔离，切换实例后重新读取；请求途中切换不跨账号重试。识图缓存绑定图片身份并限制容量，同一图片的临时签名更新可以复用摘要，替换图片则重新识别。

配图上传失败且尚未提交说说时，可以降级发布纯文字；说说已提交但结果不明时先核验最新动态，未能确认则停止自动重发，也不再额外发送纯文字。

### 💬 自动互动

- 自动点赞好友动态，并跳过自己和已处理动态；
- 自动评论好友动态，带图时可先使用视觉模型识别；
- 相册多照片动态按照片分别读取评论，同批图片共用“单条动态最多识别图片数”上限；默认综合整批识别结果生成一条评论，以“这组照片”等措辞明确指向整组，而非只评价提交落点这一张。评论正文与挂载照片编号一起生成；具体聚焦第三张就提交到第三张，不再固定落到第一张，也不逐张刷评论。单张识别失败保留其他图的原始编号，只允许选择已成功识别的照片；编号缺失或无效时不提交。其他照片仍可独立回评，同批任一照片已有机器人互动时不再发起新评论；
- 相册上传动态中的数字批次号不作为照片 `picKey`；`albumId_picKey_batchId_4` 标识须经照片查看器核对批次和 `platformSubId`，一级评论使用 `ref=photo` 和无尾缀照片目标，回评仍定位原评论楼；
- 好友在机器人说说或相册照片评论楼层下回评后自动续评；相册续评要求能从照片查看器确认原评论楼和明确 @ 机器人的回复。同楼多人分别 @ 机器人时按评论人处理，不因另一人的较新回复漏掉未答复评论；同一人连续回复同一对象时只处理最新有效回复；
- 自动回复自己说说下的一级评论与多级楼层；
- 自动回复近期动态中机器人自己相册照片的一级评论，并继续已参与的照片评论楼；使用独立相册回复接口，表单定位原一级评论，正文 @ 当前被回复者，续评提交后按返回的回复 ID 回查落点；
- 相册评论按批次、照片和楼层身份防重，已在照片中答复的回评不重复处理；提交状态未知或续评落点无法确认时停止自动重试。列表只提供部分照片标识时，必须由查看器确认同一主人、相册、`batchId` 与照片数量才能补全，不从缩略图 URL 猜标识；
- 同批照片读取不完整时暂停发起新评论，但已成功读取的照片仍可独立回评；私密评论、目标标识或回复对象无法确认的情况继续跳过，不扫描整个历史相册；
- daily_life 可用时，评论固定按动态作者、回评和续评按当前被回复者的 QQ 号读取关系档案；使用实际 QQ 空间机器人实例定位，不按昵称或触发指令的用户猜测关系；
- 关系摘要独立保留，支持档案名、别名、熟悉称呼与空间昵称对应；没有档案或无法确认实例时使用中性称呼，不额外导入私聊摘要、备忘录和约定；
- 合并好友动态和“与我相关”入口，提高提及与回评命中率；
- 使用评论 ID、回复目标与楼层关系校验落点，降低回错楼层的概率。

## 🪄 自然语言工具

开启 LLM 工具调用后，管理员或已配置的接收对象可以通过自然语言使用：

| 工具 | 职责 |
| :--- | :--- |
| <code>daily_share</code> | 生成并发送文字、新闻长图、配图、视频、语音或 QQ 空间分享 |
| <code>news_link</code> | 查询最近新闻快照中的链接、摘要、来源或列表，不重新抓取新闻 |
| <code>qzone</code> | 查看、发布、点赞、评论说说，以及读取或评论相册照片 |
| <code>qzone_auto_interact</code> | 手动触发自动点赞、评论、续评和自己说说、近期相册照片回评 |

示例：

| 说法 | 结果 |
| :--- | :--- |
| “分享一下今天的心情” | 生成并发送当前会话分享 |
| “看看微博热搜图片版” | 发送微博热搜长图 |
| “刚才热搜图第 3 条链接发我” | 从当前目标的新闻快照返回原文链接 |
| “给我来一份 60s 新闻” | 发送每天 60s 读世界长图 |
| “看一下我的空间，给第 2 条评论一句” | 获取说说后生成自然评论 |
| “把第 2 条评论为‘今天很精神’” | 直接发送用户给定的评论 |
| “现在扫一下 QQ 空间自动互动” | 手动运行自动互动任务 |

普通用户只能操作自己的 QQ 空间；发布、操作其他用户或运行全局扫描需要管理员权限。

## 🎮 手动指令

自然语言适合日常使用，<code>/分享</code> 指令用于确定性触发、配置与排障。

| 指令 | 功能 |
| :--- | :--- |
| <code>/分享 [类型]</code> | 发送问候、新闻、心情、知识、推荐、自动、60s 或 ai |
| <code>/分享 新闻 [源] 图片</code> | 发送指定新闻源长图 |
| <code>/分享 [类型] 广播</code> | 向配置中的全部群聊和私聊发送 |
| <code>/分享 [类型] 空间</code> | 发布到 QQ 空间 |
| <code>/分享 添加当前</code> | 将当前会话加入普通分享目标 |
| <code>/分享 添加当前 早报</code> | 将当前会话加入早报目标 |

“广播”建议只由管理员手动执行，避免 LLM 误触批量发送。

## 🖥️ 仪表盘

插件页面提供以下管理能力：

- **总览**：自动分享状态、当前时段、接收目标、定时任务与生成进度；
- **目标**：群聊、私聊、机器人实例、独立时间与独立类型序列；
- **手动分享**：选择目标、分享类型与新闻源；
- **动态与媒体**：查看文案、图片、视频和分享历史，支持单条或批量删除记录及其受管本地媒体文件；
- **QQ 空间**：查看动态、发布、点赞、评论、删除和查看详情；
- **设置**：管理常用配置，并由 schema 补齐其他配置项；
- **失败记录**：仅记录整条分享未能完成的失败原因，并按支持的任务类型重试；图片、视频或语音回退不会错误计入整条分享失败。

## ⚙️ 配置分组

| 分组 | 用途 |
| :--- | :--- |
| <code>enable_auto_share</code> | 自动分享总开关 |
| <code>receiver</code> | 群聊、私聊、独立时间和独立类型序列 |
| <code>contact_aliases</code> | 本地用户称呼映射 |
| <code>content_library</code> | 知识库、推荐库和类型前缀 |
| <code>extra_shares</code> | 每天 60s、AI 资讯快报、早报目标和 QQ 空间同步 |
| <code>basic_conf</code> | LLM、单次逻辑调用总超时、全局定时、时段序列、显示范围和去重 |
| <code>context_conf</code> | 生活上下文、聊天历史、群聊热度和 MemOS |
| <code>news_conf</code> | 新闻接口、新闻源、短链接和联网证据 |
| <code>image_conf</code> | 配图、新闻长图、视频和个人微信图片处理 |
| <code>tts_conf</code> | 语音生成、允许类型和仅发送语音 |
| <code>qzone_conf</code> | QQ 空间实例、定时、序列、配图与自动互动 |

四组目标列表只由仪表盘目标管理或 `/分享` 目标指令维护，普通设置保存不会改写它们。设置变更会自动保存，重新进入设置页时会自动读取最新配置；发生版本冲突时会自动加载服务端最新设置。

推荐起步方式：

- **纯文字**：配置接收目标，保持媒体能力关闭。
- **新闻长图**：开启新闻接口与热搜长图，选择新闻源和数量。
- **生活感分享**：安装并启用生活插件即可联动生活状态，聊天历史按需开启。
- **图文、视频或语音**：安装生活插件，再按需开启对应媒体能力。
- **QQ 空间**：启用 QQ 空间或自动互动，并确认 OneBot 登录态能力可用。

## 🔗 与 daily_life 联动

插件只通过 <code>astrbot_plugin_daily_life</code> 的公开入口联动，不读取其数据库或内部运行时，也不直接调用其搜索工具。生活上下文只调用 <code>get_share_context(target_umo)</code>，未提供新入口的生活插件需同步更新后才能提供生活上下文。

| 联动能力 | 行为 |
| :--- | :--- |
| 生活上下文 | 固定按当前目标读取公开接口，无独立开关；群聊文案仅选安全状态，配图保留主角外观，私聊继续读取目标隔离的生活材料 |
| QQ 空间聊天表达 | 固定联动 daily_life，无独立开关；说说、评论、回评分别通过 `qzone_post`、`qzone_comment`、`qzone_reply` 场景读取同一表达软偏好，保持各自公开边界 |
| 联网检索 | 无独立开关，由生活插件统一决定是否搜索、搜索策略、提供商与失败处理；新闻接口摘要足够时不再检索 |
| 配图、视频、语音 | 复用生活插件媒体能力；配图默认使用 daily_life 当前生成方式的第一个可用生图通道，不单独指定模型。人物配图以角色参考图锁定脸部身份和体态，当天发型、妆容、美甲与服装仅覆盖可变造型 |
| 活动回传 | 私聊、群聊沿用目标隔离的活动回传；QQ 空间成功发布和互动登记幂等公开事件，不混入私聊、不结算其他动作 |
| MemOS | 按生活插件设置同步长期记忆 |

QQ 空间说说、自动评论和回评固定联动 daily_life，语气与表达节奏统一在 daily_life 的“聊天表达 / 短句风格软偏好”中调整，不再提供独立联动开关，旧开关残留值不参与生成。五类说说共用“随手发一条状态”的公开任务，围绕这次在意的一点，用角色平时说话的口吻表达，意思说完就停，不要求铺景、抒情或感悟收尾。不再叠加模板固定字数、开头或括号标题，也不自动添加知识/推荐类型前缀；类型前缀配置仍供其他平台使用，私聊和群聊不受影响。

QQ 空间不再提供独立“说说输出格式”，也不会复用普通分享输出格式；旧配置残留值不参与生成，设置页也不再展示或保存该字段。普通分享的格式设置继续独立生效。

文案从同一次公开生活快照选取天气、当前状态和实际自主活动；暂停、待结算不当作完成，不把整天计划、文学化基调、地点记忆或旧文案作为写作材料。居住地背景待刷新时，旧天气、地点、穿搭、心情和日程不参与文案或配图；正常背景下配图继续保留外观和穿搭资料。

生成后调用 daily_life 的公开表达检查，已自然则保留，过度铺陈则围绕一个主要意思简化，不新增事实、不机械截断。80 字是说说发布保护上限，不是要求写满的模板，也不使用私聊字数设置；检查不可用时保留原文，仍过长则取消发布。近期已发正文不进入模型，只用于最终正文忽略空白的重复检查，命中时取消发布；这不是语义重复判定。新闻、知识和推荐仍使用真实资料。

生图模型与通道顺序统一在 daily_life 中配置。daily_share 不再提供文生图、图生图模型字段，也不读取旧字段残留值；daily_life 根据参考图判断生成方式，从对应列表的首个可用通道开始，失败时沿用生活插件的后续通道容错。

自动评论和回评参考对应场景的表达偏好；目标隔离的长期语气、表达习惯和避免项仅作软参考，不导入临时偏好、证据或私聊内容。不同场景不改变单条互动任务和回复对象规则；多图评论继续综合识图，正文与照片落点一起生成，不单独润色而打断绑定。旧配置中的独立评论和回评风格值不再读取，也不再由设置页保存。

生活上下文与群聊生活状态固定联动，移除 `enable_life_context`、`life_context_in_group` 和 `enable_web_search`，旧字段残留值不参与运行或设置页保存。群聊默认只使用天气、心情、时段、忙碌度和当前实际活动；“群聊展示日程细节”仍是独立披露授权，开启后也只增加结构化日程及其执行状态，不导入关系档案、私聊摘要、备忘录或地点档案，不将过时或未来计划当作已完成。自动发布、自动互动、聊天历史、MemOS 和媒体开关保持独立。

QQ 空间表达不套用私聊或闲时回复的字数限制、聊天分段发送、标点清洗，也不导入私聊记录。说说第一人称、评论回复对象和公开隐私边界继续由 daily_share 的 QQ 空间场景规则约束。需同步更新并重载 daily_life 和 daily_share；daily_life 关闭聊天表达或接口不可用时，说说回退到同一状态任务的自然公开表达，不恢复旧作文式模板；评论和回评使用默认表达，仍可正常发布和互动。

生活插件未安装、未启用、未完成初始化、正在重载或调用失败时，对应增强会自动跳过，不影响插件基础能力；媒体进度会区分“生活插件不可用”“未返回有效结果”“视频生成超时”和“生成调用失败”，并按当前异步任务隔离状态，便于定位配置或接口问题。媒体失败但其余内容成功送达时，记录保持成功并标记为降级，不会进入整条分享失败的重试队列。

已受理的异步图片、视频不按失败降级：生活插件持久管理原媒体任务，分享插件保存原文案、配图、目标和媒体归属；超时或重载后只查询原任务，取得成品后续接原分享，不重新生成或套用旧私聊事件。同一目标已有待续接分享时，自动调度不再生成新任务。受理前的通道错误保留 daily_life 的顺序容错，受理后的临时查询错误不切换通道；提供商明确失败后才按原媒体降级规则处理。

恢复仍检查自动发布开关、接收目标和智能调度静默时段。定时分享等待超过两小时、手动分享超过一天不补发过期文案，但保留媒体成品；提交结果不明时停止自动重发并记录日志，需先核对原发布目标。QQ 空间公开回执暂时无法回传时持久排队，恢复后按事件编号去重，不影响已经成功的发布。语音按正文实际语义选择声音风格，失败时保持原文和中性风格，不再由类型或时段固定套情绪。

## 🧪 开发与验证

~~~bash
pytest -q
python -m unittest discover -s tests
python -m ruff check .
python -m ruff format --check .
~~~

测试覆盖配置、命令、新闻解析、新闻快照、调度恢复、多平台路由、权限、媒体、LLM 工具、QQ 空间、自动互动、仪表盘、数据库结构校验和插件生命周期。

`tests/testhealth.py` 补充账号隔离、聊天等待预算、并发缓存与容量、取消清理、模型超时、缓存 token 统计及视觉构图回归。模型缓存 token 仅按服务实际返回值统计，可在调试日志的 `cached_input` 字段检查，不保证服务端命中率。

文本提示词按“固定规则 → 本次时间、对象和事实 → 输出要求”组织；QQ 空间文风规则与动态生活资料分别传入，视觉提取也共用固定系统规则，人物与静物条件放在本次输入。本次不缩减人设长度来凑缓存，不复用不同用户的生成结果，也不添加占位文字或强制开启提供商不支持的缓存参数。

用量日志同时覆盖文本和 QQ 空间识图，显示本次及同一模型服务累计的缓存 token 占比、`有缓存调用=命中次数/有用量调用次数`。占比是缓存输入 token ÷ 总输入 token，两项指标不应混用；无用量或默认全零用量不计入统计，累计值在重载后重新开始。若中转不返回缓存 token，日志里的零不能证明其内部完全没有缓存。图片摘要和短链接的本地复用也不计作模型缓存命中。

`tests/testpromptcache.py` 验证资料变化后的稳定前缀、对象资料隔离、识图用量口径和发布降级边界。详细体检结果见 [2026-10-08 体检报告](./docs/health-2026-10-08.md)。
