<a id="quick-start"></a>

## 🚀 快速开始

1. **📦 安装并启用**
   - 在插件市场安装 <code>astrbot_plugin_daily_share</code>。

2. **🎯 添加接收目标**
   - 在要接收分享的当前会话发送 <code>/分享 添加当前</code>。
   - 或进入仪表盘，填写 QQ 号、群号或其他平台的会话 ID。
   - 多机器人实例时，在目标卡片中选择负责发送的机器人；单实例会自动绑定。

3. **📝 选择分享方式**
   - 只想发送文字：保持媒体能力关闭即可。
   - 需要自动分享：开启 <code>enable_auto_share</code> 并选择触发方式；生活驱动按真实材料自主选题，其他定时模式按配置时间和类型序列执行。
   - 需要指定内容：使用 <code>/分享 心情</code>、<code>/分享 新闻</code> 或自然语言触发。

4. **🧩 按需安装生活插件**
   - 需要生活状态、联网证据、配图、视频、语音或 MemOS 时，安装
     [astrbot_plugin_daily_life](https://github.com/siciyuanweilai/astrbot_plugin_daily_life)。
   - 完整联动需 daily_life 插件，详见[联动说明](#daily-life)。
   - 生活插件未安装时，纯文字分享、新闻接口、新闻长图、定时任务和普通平台发送仍可独立使用。

5. **🧪 完成首次验证**
   - 发送 <code>/分享 心情</code>，确认当前会话能收到文字分享。
   - 发送“看看微博热搜图片版”，确认新闻接口和长图发送链路。
   - 发送“分享一下今天的心情”，确认自然语言工具调用。

6. **🖥️ 打开仪表盘**
   - 在网页管理后台的插件详情页进入日常分享仪表盘。
   - 可继续调整目标、定时、类型序列、新闻源、媒体、QQ 空间和失败重试配置。

## 📝 分享内容

| 类型 | 内容来源 | 适合场景 |
| :--- | :--- | :--- |
| <code>问候</code> | 当前时段、生活状态、聊天上下文 | 早安、晚安、日常招呼 |
| <code>新闻</code> | 热搜接口、新闻摘要、新闻长图 | 热点速览与原文追问 |
| <code>心情</code> | 当前状态、人设与上下文 | 文字、语音、配图或视频 |
| <code>知识</code> | 自定义知识库与联网证据 | 科普、技巧与趣味知识 |
| <code>推荐</code> | 自定义推荐库与联网证据 | 书影音、应用与生活推荐 |
| <code>自动</code> | 当前时段与类型序列 | 无需手动指定类型 |

知识库和推荐库支持自定义分类、子话题与类型前缀。成功分享会写入历史，用于去重、仪表盘展示和后续上下文参考。

<a id="news"></a>

## 📰 新闻与快照

支持微博、知乎、B站、抖音、快手、头条、百度、腾讯、夸克、36氪、51CTO、A站、爱范儿、网易、新浪、澎湃、第一财经、财联社等新闻源。

- 新闻优先使用接口提供的摘要、正文与原文链接。
- 背景资料不足时，可通过生活插件的公开检索入口补充证据。
- 新闻源可固定选择，也可从配置列表中随机选择。
- QQ 群聊和私聊会优先下载远程长图后发送，提高富媒体稳定性。
- 查询链接时不会重新抓取远程新闻，只读取成功发送时保存的 JSON 快照。
- 支持按序号、标题或摘要追问原文链接；序号可使用阿拉伯数字、全角数字或中文数字。

快照查询规则：

| 查询方式 | 读取内容 |
| :--- | :--- |
| 未指定新闻源 | 当前目标最后一次成功发送的新闻快照 |
| 指定新闻源 | 当前目标中该新闻源最后一次成功发送的新闻快照 |

例如依次发送：

~~~text
09:09  微博热搜
10:00  抖音热搜
11:00  微博热搜
~~~

此时默认查询读取“11:00 微博”，指定抖音读取“10:00 抖音”，指定微博读取“11:00 微博”。后台抓取和发送失败不会覆盖已有快照。

## ⏰ 分享触发与序列

| 调度方式 | 说明 |
| :--- | :--- |
| 生活驱动（默认） | 依托 daily_life 的新经历，结合人设、感受、关系和近期联系决定是否分享；允许全天安静 |
| 固定时间 | 按每日指定时间执行 |
| 随机时段 | 在配置时段内生成随机执行时间 |
| 智能定时 | 结合配置策略生成执行任务 |
| 高级 Cron | 支持标准 5 位表达式（星期字段按 crontab 约定：0/7 为周日） |
| 独立目标定时 | 每个群聊或私聊可设置自己的时间和类型序列 |
| QQ 空间分享 | 可独立选择生活驱动或定时模式 |

普通分享、早报和 QQ 空间分别使用独立的随机延迟。随机时段的结束时间必须晚于开始时间，不支持跨天；智能定时的勿扰时段支持跨天。随机时段与智能定时任务会写入数据库，插件重启后可恢复尚未完成的任务。

目标卡片规则：

- 独立时间留空时跟随全局触发模式。
- 独立序列留空时跟随全局类型序列。
- 同时设置独立时间和独立序列时，该目标完全独立运行。

## 🧠 上下文与媒体

分享可结合当前时间、角色人设和生活状态，也可按需读取：

- 当前穿搭与外观、身体状态和近期生活片段；
- 当前会话的聊天历史、关注事项与表达习惯；
- 群聊活跃程度、已分享内容和 MemOS 长期记忆。

资料按接收目标隔离，公开场景不带入私聊记忆。生活状态、媒体和长期记忆由 daily_life 提供，聊天历史等能力可独立调整。

| 媒体 | 使用方式 |
| :--- | :--- |
| 配图 | 按文案生成；角色入镜时保留身份，当天穿搭与外观优先于参考图中的旧造型 |
| 视频 | 由生成配图制作；与配图择一发送，QQ 空间暂不发布视频 |
| 语音 | 适用于问候、心情等允许类型，可配置仅发送语音 |
| 个人微信图片 | 使用独立发送副本，适配个人微信发送要求 |

媒体生成失败时继续发送其余可用内容；异步任务尚未完成或结果暂时无法确认时，保留原任务继续查询，超时或重载后可续接。等待不代表已发送或保证续发成功。只有确认送达后才记入成功历史并回传活动与记忆；局部媒体失败仅在日志、面板进度和历史记录保留具体原因，不向接收方额外发送失败提示。任务丢失或成品文件缺失则记录失败，详见[与 daily_life 联动](#daily-life)。

## 🧭 平台与目标

| 平台 | 支持场景 | 目标填写 | 注意事项 |
| :--- | :--- | :--- | :--- |
| QQ / OneBot (<code>aiocqhttp</code>) | 私聊、群聊、QQ 空间 | QQ 号或群号 | 多实例时选择负责发送的机器人 |
| QQ 官方机器人 (<code>qq_official</code>) | 私聊、群聊 | 官方 OpenID 或 <code>/sid</code> 完整标识 | 使用独立实例 ID，群聊需开启主动发言；不支持 QQ 空间 |
| 个人微信 (<code>weixin_oc</code>) | 个人私聊 | 会话 ID 或 <code>/分享 添加当前</code> | 需要框架已保存对应 <code>context_token</code> |
| WebChat / 其他平台 | 取决于适配器能力 | 优先使用 <code>/sid</code> 输出 | 主动发送能力由适配器决定 |

只有一个可用机器人实例时，仪表盘会自动绑定；存在多个实例时必须明确选择。插件内部保存完整会话标识，避免多机器人实例串线。

QQ 官方机器人建议使用更新后的 AstrBot 官方适配器。在目标私聊或群聊中发送 `/分享 添加当前`，即可保存当前会话；也可将 `/sid` 的完整输出填入仪表盘。官方用户/群 OpenID 与真实 QQ 号/群号不同，请勿混用。官方平台的称呼优先使用会话可提供的昵称、人设称呼或本地别名，聊天历史读取 AstrBot 已保存的记录，不调用 OneBot 查询。

官方群聊需在手机 QQ 的机器人设置中开启“机器人主动在群聊内发言”；需要参考群聊上下文时可开启“获取群内全部消息”，详见 [AstrBot 官方接入说明](https://docs.astrbot.app/platform/qqofficial/websockets.html)。首次配置或适配器重启后，先在目标群 @机器人发送一条消息，让适配器识别群会话，再执行主动分享。文字、图片、语音和视频交由 AstrBot 适配器发送，权限、媒体格式与发送额度遵循官方平台限制；QQ 空间发布、点赞、评论和回评仍需另配 OneBot 实例。

<a id="qzone"></a>

## 🌐 QQ 空间

### ✨ 发布与操作

使用 OneBot，并确认适配器支持 `get_cookies`。QQ 空间自动使用唯一可用的 OneBot；有多个 OneBot 时，先在需要使用的机器人会话中执行空间命令，后续空间任务使用该实例。重载插件后需重新执行一次。

- 发布文字或图片说说，查看自己或指定用户的动态与详情；
- 点赞、评论说说及相册动态，删除自己发布的说说；
- 按相册 ID 和照片 `picKey` 查看照片、读取评论或发表评论。

登录态和查询缓存按机器人实例隔离。配图上传失败且尚未提交说说时可改发纯文字；提交结果不明时先核验，不自动重复发布。

发布说说支持 **@ 好友**：在正文任意位置插入 `@{uin:QQ号,nick:昵称}`，将 QQ 号和昵称替换为好友的真实信息，支持多个好友。例如：

```text
今天和 @{uin:123456789,nick:好友甲} 一起出游，感谢 @{uin:987654321,nick:好友乙} 推荐的路线！
```

### 💬 自动互动

开启自动互动后，可按配置点赞好友动态、发表评论，并回复自己说说和近期相册照片下的评论。

- **先看内容再接话**：带图动态可使用视觉模型识别，已识别内容可供后续回评复用。
- **整组或单张评论**：通过“整组照片评论概率”切换，100% 始终评论整组，0% 始终选一张照片，中间值按概率随机（默认 100%）。整组综合已识别照片，单张模式选择并聚焦一张照片；每批只发一条主体评论。无法核实上传批次时沿用单张评论。重试沿用原落点与正文，切换模式共用识图上限和缓存。
- **相册回评跟随原楼**：上传批次评论与单张照片评论分别读取、提交和防重；概率回评跟随被回复评论的位置，不参与主体评论模式随机。
- **主动回复其他用户**：0 关闭；生活驱动模式下，大于 0 允许结合关系、内容和注意力自主决定，其他模式按 0–100% 概率选择。与主体评论独立判断、防重和计数。同一条说说或相册动态需要两者时，先发表主体评论，再结合已发送的主体评论与动态、楼层上下文生成回评。两类动作分别受“评论数量”上限约束，设为 1 时最多各发 1 条。
- **主动回评人数上限**：可设 1–10 人，默认 1 人。优先考虑最新的合格评论，按不同用户计算人数；同一用户多条顶层评论只选一条，已主动回评用户不会重复参与。人数在防重记录有效期内累计，调高上限可继续参与其他用户；每轮仍受“评论数量”限制，对方后续回复 Bot 的续评不占人数名额。上限只控制资源，不要求用满。
- **延续已有交流**：好友明确回复或 @ 机器人后可继续接话，按动态、照片和评论楼层防重。
- **谨慎处理不确定结果**：目标、权限、楼层或提交结果无法确认时跳过或停止自动重试。

daily_life 可提供公开场景的表达习惯与对象称呼，不导入私聊摘要、备忘录或约定。

## 🪄 自然语言工具

开启 LLM 工具调用后，管理员或已配置的接收对象可以通过自然语言使用：

| 工具 | 职责 |
| :--- | :--- |
| <code>daily_share</code> | 生成并发送文字、新闻长图、配图、视频、语音或 QQ 空间分享 |
| <code>news_link</code> | 查询最近新闻快照中的链接、摘要、来源或列表，不重新抓取新闻 |
| <code>qzone</code> | 查看、发布、点赞、评论说说，以及读取或评论相册照片 |
| <code>qzone_auto_interact</code> | 手动触发自动点赞、评论、续评和自己说说、近期相册照片回评 |

示例：

| 说法 | 结果 |
| :--- | :--- |
| “分享一下今天的心情” | 生成并发送当前会话分享 |
| “看看微博热搜图片版” | 发送微博热搜长图 |
| “刚才热搜图第 3 条链接发我” | 从当前目标的新闻快照返回原文链接 |
| “给我来一份 60s 新闻” | 发送每天 60s 读世界长图 |
| “看一下我的空间，给第 2 条评论一句” | 获取说说后生成自然评论 |
| “把第 2 条评论为‘今天很精神’” | 直接发送用户给定的评论 |
| “现在扫一下 QQ 空间自动互动” | 手动运行自动互动任务 |

普通用户只能操作自己的 QQ 空间；发布、操作其他用户或运行全局扫描需要管理员权限。

## 🎮 手动指令

自然语言适合日常使用，<code>/分享</code> 指令用于确定性触发、配置与排障。

| 指令 | 功能 |
| :--- | :--- |
| <code>/分享 [类型]</code> | 发送问候、新闻、心情、知识、推荐、自动、60s 或 ai |
| <code>/分享 新闻 [源] 图片</code> | 发送指定新闻源长图 |
| <code>/分享 [类型] 广播</code> | 向配置中的全部群聊和私聊发送 |
| <code>/分享 [类型] 空间</code> | 发布到 QQ 空间 |
| <code>/分享 添加当前</code> | 将当前会话加入普通分享目标 |
| <code>/分享 添加当前 早报</code> | 将当前会话加入早报目标 |
| <code>/分享 昵称 [名称]</code> | 设置当前会话的本地称呼 |
| <code>/分享 早报空间 开启/关闭</code> | 控制早报同步到 QQ 空间 |

“广播”建议只由管理员手动执行，避免 LLM 误触批量发送。

<a id="dashboard"></a>

## 🖥️ 仪表盘

插件页面提供以下管理能力：

- **总览**：自动分享状态、当前时段、接收目标、定时任务与生成进度；
- **目标**：群聊、私聊、机器人实例、独立时间与独立类型序列；
- **手动分享**：选择目标、分享类型与新闻源；
- **动态与媒体**：查看文案、图片、视频和分享历史，支持单条或批量删除记录及其受管本地媒体文件；
- **QQ 空间**：查看动态、发布、点赞、评论、删除和查看详情；
- **设置**：管理常用配置，并由 schema 补齐其他配置项；
- **失败记录**：仅记录整条分享未能完成的失败原因，并按支持的任务类型重试；图片、视频或语音回退不会错误计入整条分享失败。

新发布记录统一区分网络 URL 与本地图片路径，预览和放大支持插件图片、daily_life 生成图片与 AstrBot 附件。AstrBot 共享附件只允许读取；本次图片修复对新记录生效，已有记录不迁移、不回填。

<a id="daily-life"></a>

## 🔗 与 daily_life 联动

daily_share 可独立完成文字分享、新闻和定时发送。安装 [daily_life](https://github.com/siciyuanweilai/astrbot_plugin_daily_life) 后，可让分享承接角色的生活与交流；完整协作需同步更新 daily_life 配套实现并重载两端插件；本次续接改写需要生活侧支持表达检查状态回执与语义重排。

| 能力 | 使用说明 |
| :--- | :--- |
| 生活驱动 | 结合真实经历、当前状态和对象关系，自主选择分享、等待或放下 |
| 表达与记忆 | 沿用角色日常口吻，结合近期交流和相关记忆，支持按需接入 MemOS |
| 配图、视频、语音 | 在 daily_share 开启所需能力，模型和通道统一在 daily_life 配置 |
| 联网资料 | 复用生活侧检索能力，保留来源依据；新闻资料不写成亲身经历 |
| 主动互动 | 协调分享与生活侧主动联系；好友动态点赞意愿可在 QQ 空间设置中单独调整 |
| 成品续接 | 保留可用媒体，结合最新对话和生活变化重评；改写沿用当前语气与排版，确认送达后回传记录 |

生活驱动和智能定时默认私聊/群聊至少间隔 **45 分钟**、QQ 空间至少 **90 分钟**，可在设置中调整；连续联系未获回应时进一步放缓。睡眠、忙碌或免打扰时暂缓，时间到达只重新考虑是否互动。

私聊资料按目标隔离，公开渠道只使用允许公开的信息；已经提交但结果不明的任务不自动重发。生活插件不可用时，基础分享继续运行，需要重新检查表达的续接成品保留等待。

B站分享的版本要求和配置见[下方说明](#bilibili)，具体变化见[更新日志](./CHANGELOG.md)。

<a id="bilibili"></a>

## 📺 B站分享

配套协作使用公开接口：生活侧独立回访、闲时主动消息、通话邀请和 B站主动私信/公开提及，共用分享侧按目标保存的主动联系记录；B站自主动态有独立的最短间隔设置，默认 90 分钟。正常回复、被动私信及明确约定的提醒保留原行为。节奏协调服务重载或异常时，相关自主任务暂缓；未安装或未启用配套分享插件时，生活侧沿用自身的联系规则。

行动投影按稳定动作链和依赖关系提供经历编号，只有所有步骤取得成功回执才将整段经历视为完成。实际外观和行动阶段纳入发送前快照，旧成品继续走保留、改写、等待或归档流程。搜索沿用生活侧 Grok/Tavily 配置，并保留结构化来源、质量和未解决的问题，不增加话题关键词或提示词分支。

账号登录仍在 daily_life，通过 `/B站登录` 管理。此能力不新增第二套 Cookie 或发送客户端。新版 B站正文可能位于 Opus 字段，配套适配层需同时核对实际正文与图片，避免已经发出后持续待核。

工作台入口：**设置 → B站**。可管理B站分享开关、主动与公开互动、动态配图，修改后自动保存；与 AstrBot 插件配置中的 `bilibili_conf` 使用同一份配置。

| 设置 | 默认 | 作用 |
| --- | --- | --- |
| `enable_auto_share` | 沿用原设置 | 总自动分享开关，必须开启 |
| `bilibili_conf.enabled` | 关闭 | 启用 B站动态与对外分享 |
| `bilibili_conf.manage_interactions` | 开启 | 统一安排主动 @、主动私信推荐、公开评论回复和弹幕表达 |
| `bilibili_conf.enable_image` | 开启 | 优先使用所选素材的公开图片，没有现成图片时生成一张；关闭后允许新建纯文字动态 |

生活侧继续决定观看、收藏、生活注意力和是否有交流意愿，维护绑定身份与联系节奏，承接被动私信；分享侧根据候选决定具体渠道与措辞。公开动态只使用实际公开浏览、当前外观和明确公开的作品。主动 @ 仍须完成本人 B站身份验证，普通观众的公开评论也可以回应。

B站独立选择素材和发布时间，复用 QQ 空间的“决定是否分享 → 生成短文案 → 准备配图 → 发送前复核 → 发布并记录回执”方法，不转发或同步 QQ 空间帖子。正文使用同一公开动态生成与标点清洗流程，通常一两句，最多 80 字；超过长度或与近期本账号动态重复时暂缓，不机械截断，不使用决策模型返回的长文直接发布。

开启动态配图后，可选择最多 9 张所选素材的现有公开图片；未指定图片时优先使用该素材的首张可用图片，没有现成图片则围绕最终短文案和公开生活资料生成一张。新生图同时遵守全局 AI 配图开关，并使用与 QQ 空间相同的人物判断、外观、构图和提示词流程。关闭动态配图才允许新建纯文字动态。生成期间等待原任务，重启查询原任务；生成或上传失败不自动改为纯文字。上传逐张保存回执，最终发布结果不明时核对原动态，不重复发送。关闭配图可暂停待发图文；关闭总自动分享时，生活侧也会暂停这些内容的自动发送。

## 🧪 开发与验证

在已配置 AstrBot 和插件运行依赖的 Python 3.12 环境中，从插件根目录执行检查；pytest 和 Ruff 按需安装：

~~~bash
python -m pytest -p tests.pytestplugin -q tests
python -m tests
python -m ruff check .
python -m ruff format --check .
~~~

测试覆盖配置、指令、新闻、调度、多平台路由、权限、媒体、QQ 空间、仪表盘和生命周期。测试模块隔离运行，`python -m tests` 汇总实际用例数，`pytest` 每个模块显示一个测试项。两项真实跨插件接口测试需要同级 `astrbot_plugin_daily_life` 源码及其运行依赖；未提供源码时明确跳过，汇总结果同时显示跳过数。

`python -m tests tests.testcachehealth tests.testperformance tests.testhealth` 验证缓存、并发与聊天响应边界。新闻和百科资料使用有界短缓存；最新生活状态、主动联系判断与生成文案每次重新核对，保持自然互动的连续性。

可用 `python -m tests tests.testauditfixes` 单独运行缺陷回归，或用 `python -m tests tests.testqzonecommentjoin` 验证概率回评、执行顺序与独立防重。测试中的模型请求和最终消息传输使用替身，不产生实际调用或消息。
